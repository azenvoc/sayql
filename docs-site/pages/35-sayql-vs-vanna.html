Vanna is an open-source Python framework for adding a text-to-SQL chat to an app you build. Its repository was archived on 29 March 2026, so it gets no more updates. SayQL is a desktop SQL client that lets you and your AI agents query your databases while keeping rows and chosen columns away from the AI.

Choose Vanna, or a maintained fork, to embed text-to-SQL in a product for your own users. Choose SayQL to give people and AI agents governed access to your own databases.

What Vanna does better

  • Embeds in your own web app or SaaS for your end users, with a drop-in chat component that uses your existing sign-in. source
  • Connects to more warehouses, including Snowflake, BigQuery, Redshift, Oracle, DuckDB and ClickHouse. source
  • Can get more accurate from trained question–SQL pairs, documentation and saved successful queries. source
  • Streams charts and written summaries along with tables. source
  • A Python framework you can extend with your own tools and hooks, under the MIT licence. source

How SayQL handles AI access

  • Counts, not rows, by default. For each connection you choose what AI apps see of results: nothing, counts and summaries, masked rows or all rows. More
  • Columns that never reach the AI. Mark a column never send and any query that could read it is refused, and it's withheld from results. More
  • Read-only, enforced. Every statement is checked before it runs and runs in a read-only transaction; AI apps can't change data. More
  • A record of what AI ran. See every query each AI app ran, and block an app in one click. On the team server, one log covers every person and agent. More
  • Per-agent keys on your own server. The self-hosted team server gives each agent its own key, databases, tables and rows. More

Questions

Does Vanna send query results to the AI?

Query results: in 2.0 the run_sql tool sends up to 1,000 characters of the result to the model, which summarises the data. source In SayQL: schema by default. Per connection you choose what AI sees of results: nothing, counts and summaries (default), masked rows, or all rows. source

Can Vanna keep a column away from the AI?

No built-in setting; a hook you can implement to redact arguments does nothing by default. source In SayQL, yes: columns marked never send are refused in any form and withheld from results. source

Is Vanna read-only for AI?

Not enforced: the runner executes any statement and commits; relies on the database login's permissions. source In SayQL: read-only by default: statements are checked before they run and run in a read-only transaction; AI apps can't change data. source

Does Vanna have an MCP server for AI agents?

No official MCP server (third-party wrappers exist) source In SayQL, yes: a local MCP server for Claude Code, Cursor and others, and an HTTP gateway on the team server. source
