MCP Toolbox for Databases is Google's open-source MCP server that gives AI agents tools for your databases. It's infrastructure for developers: you define tools in YAML and run the server. SayQL is an app for people and agents, with an MCP server and a self-hosted gateway built in.

Choose MCP Toolbox to build agents across many cloud sources with fixed-SQL tools and sign-in from your identity provider. Choose SayQL for a ready app where people ask in plain English and agents get results at the level you choose, with columns kept from the AI, out of the box.

What MCP Toolbox for Databases does better

  • Many more sources: 51 integrations, including managed cloud databases such as BigQuery, Spanner, AlloyDB and Snowflake, and NoSQL and graph stores. source
  • Tools with fixed SQL: a developer writes the query and the agent only fills in bound parameters. source
  • Identity-aware tools: sign-in with Google or OIDC, and parameters filled from the caller's token, so rows are scoped per end user. source
  • A central server for many agents and apps, with connection pooling, deployable to Cloud Run, Kubernetes or Docker. source
  • Built-in OpenTelemetry, and first-party SDKs for LangChain, LlamaIndex, Genkit and ADK. source

How SayQL handles AI access

  • Counts, not rows, by default. For each connection you choose what AI apps see of results: nothing, counts and summaries, masked rows or all rows. See what AI apps may see.
  • Columns that never reach the AI. Mark a column never send and any query that could read it is refused, and it's withheld from results. See never-send columns.
  • Read-only, enforced. Every statement is checked before it runs and runs in a read-only transaction; AI apps can't change data. See how queries run safely.
  • A record of what AI ran. See every query each AI app ran, and block an app in one click. On the team server, one log covers every person and agent. See agent activity.
  • Per-agent keys on your own server. The self-hosted team server gives each agent its own key, databases, tables and rows. See SayQL for teams.

Questions

Does MCP Toolbox for Databases send query results to the AI?

What each tool returns goes back to the agent; no built-in summarising or masking (optional post-processing, or Google Cloud Model Armor) source In SayQL: schema by default. Per connection you choose what AI sees of results: nothing, counts and summaries (default), masked rows, or all rows. source

Can MCP Toolbox for Databases keep a column away from the AI?

Not built in: leave the column out of a fixed-SQL tool, or mask with Model Armor on Google Cloud. source In SayQL, yes: columns marked never send are refused in any form and withheld from results. source

Is MCP Toolbox for Databases read-only for AI?

Fixed-SQL tools take only bound parameters; a free-form SQL tool exists for developer use. A read-only setting is documented for Cloud SQL, AlloyDB and BigQuery; otherwise use a read-only database user. source In SayQL: read-only by default: statements are checked before they run and run in a read-only transaction; AI apps can't change data. source

Does MCP Toolbox for Databases have an MCP server for AI agents?

Yes: it is an MCP server (stdio or Streamable HTTP) source In SayQL, yes: a local MCP server for Claude Code, Cursor and others, and an HTTP gateway on the team server. source
