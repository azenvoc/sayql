Chat2DB is a database client with AI chat, charts and an MCP server, available as a desktop app or a web app. SayQL is a desktop SQL client built so AI can help without seeing your rows.

Choose Chat2DB for dashboards, charts and many databases. Choose SayQL when the AI shouldn't see row values, when some columns must never reach it, and when you need to know what each AI app ran.

How SayQL handles AI access

  • Counts, not rows, by default. For each connection you choose what AI apps see of results: nothing, counts and summaries, masked rows or all rows. More
  • Columns that never reach the AI. Mark a column never send and any query that could read it is refused, and it's withheld from results. More
  • Read-only, enforced. Every statement is checked before it runs and runs in a read-only transaction; AI apps can't change data. More
  • A record of what AI ran. See every query each AI app ran, and block an app in one click. On the team server, one log covers every person and agent. More
  • Per-agent keys on your own server. The self-hosted team server gives each agent its own key, databases, tables and rows. More

Questions

Does Chat2DB send query results to the AI?

Schema and query rows: its SQL tool returns up to 200 rows to the model by default (500 at most) source In SayQL: schema by default. Per connection you choose what AI sees of results: nothing, counts and summaries (default), masked rows, or all rows. source

Can Chat2DB keep a column away from the AI?

Not found in Community's code or docs. source In SayQL, yes: columns marked never send are refused in any form and withheld from results. source

Is Chat2DB read-only for AI?

The app runs only SELECT, SHOW and DESCRIBE from the AI automatically; anything else is handed to you to review. No read-only transaction found. source In SayQL: read-only by default: statements are checked before they run and run in a read-only transaction; AI apps can't change data. source

Does Chat2DB have an MCP server for AI agents?

Yes: a built-in MCP server with tools to list objects, read schemas, run SQL and turn text into SQL. source In SayQL, yes: a local MCP server for Claude Code, Cursor and others, and an HTTP gateway on the team server. source
